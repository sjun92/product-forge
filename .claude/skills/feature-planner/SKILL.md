# Feature Planner

새 기능의 구현 계획을 세운다. 계획이 확정될 때까지 코드를 바꾸지 않는다.

---

## 호출 즉시 시작

스킬이 호출되면 **스킬 소개 없이 바로** 아래를 수행한다.

### Ruflo MCP 가용성 확인

`.mcp.json`의 `claude-flow` 서버 설정과 세션 내 MCP 도구 활성 여부를 확인한다.

- **활성 상태**: `claude_flow_spawn_agent` 등 ruflo 도구로 하위 에이전트를 위임한다.
- **비활성 상태**: "Ruflo MCP가 비활성 상태입니다. Claude가 직접 계획을 수립합니다."라고 한 줄 고지 후 진행한다. Ruflo를 사용했다고 말하지 않는다.

### 항목 파악 및 시작

1. 현재 대화에서 아래 4개 항목 중 이미 언급된 것을 파악한다.
2. 파악된 항목은 **추천값으로 제시**하며 맞는지 확인한다.
3. 파악되지 않은 항목은 **가장 중요한 것 1개**를 먼저 질문한다.

예시 — 사용자가 "즐겨찾기에 완료 필터 추가해줘"라고만 한 경우:

> 기능은 **즐겨찾기 목록에 완료 여부 필터 추가**로 잡을게요. 맞나요?
> 사용자 흐름은 어떻게 되나요? 버튼 탭(전체/미완료/완료)으로 전환하는 방식인가요, 드롭다운 필터인가요?

항목이 전혀 없는 경우: "어떤 기능을 추가할까요?"로 시작한다.

---

## 1단계: 항목 채우기

아래 4개 항목을 순서대로 채운다.  
**항목당 하나씩** 질문한다. 이미 말한 내용은 다시 묻지 않는다.  
현재 대화나 코드베이스에서 추론할 수 있으면 **추천값을 먼저 제시**하고 맞는지 확인한다.

### 항목 1: 기능
> "어떤 기능인가요?"

**추천 방법**: 사용자가 이미 설명한 경우 그 내용을 한 줄로 요약해 제시한다.  
예) "즐겨찾기 목록에 완료 여부 필터 추가 — 이렇게 잡을까요?"

### 항목 2: 사용자 흐름
> "사용자가 어떤 순서로 이 기능을 사용하나요?"

**추천 방법**: 기능 설명에서 UI 패턴을 추론해 제시한다.  
예) "버튼 3개(전체/미완료/완료)로 목록 전환 — 아니면 드롭다운 필터인가요?"

### 항목 3: 완료 조건
> "이 기능이 '잘 됐다'는 것을 어떻게 확인할 수 있나요?"

**추천 방법**: 기능 유형에 따라 기본 완료 조건 3개를 제안한다.
- 데이터 유지: 필터를 바꿔도 원본 데이터는 유지
- 빈 상태: 해당 항목이 없으면 빈 상태 안내 표시
- 기존 기능 유지: 기존 추가·삭제 기능이 계속 동작

> "이 3가지를 기본으로 잡을까요? 추가하거나 바꿀 것이 있나요?"

### 항목 4: 재사용 힌트 (선택)
> "기존에 비슷한 구현이 있나요? 없으면 넘어가도 됩니다."

**추천 방법**: 코드베이스를 이미 파악한 경우 관련 파일을 먼저 제시한다.  
예) "favorites/router.py의 필터 패턴을 재사용할 수 있을 것 같습니다. 맞나요?"

## 2단계: 완성된 내용 확인

4개 항목이 채워지면 아래 형식으로 한 번 보여준다.

```
기능: {기능}
사용자 흐름: {사용자 흐름}
완료 조건:
- {조건1}
- {조건2}
- {조건3}
재사용 힌트: {힌트 또는 없음}
```

> "이대로 진행할까요?"

---

## 3단계: 계획 실행

확인이 되면 아래를 수행한다.

```
Ruflo 멀티 에이전트 방식으로 다음 기능의 구현 계획을 세워줘.
기능: {기능}
사용자 흐름: {사용자 흐름}
완료 조건:
{완료 조건 목록}
기획은 흐름과 빠진 요구사항을,
개발은 기존 구조와 변경 파일을,
테스트·리뷰는 오류 상황과 회귀 위험을 확인해줘.
기존 구현을 먼저 찾아 재사용하고,
계획·변경 범위·검증 방법을 보여준 뒤 멈춰줘.
내가 "진행해줘"라고 답한 뒤에만 구현해.
구현 후에는 실제 테스트 결과와 확인하지 못한 항목을 알려줘.
```

- 의존성 설치 금지
- 비밀값·개인정보 원문 출력 금지
- 추정은 `[추정]`, 확인된 사실은 `[사실]`로 구분
- "진행해줘" 승인 전 구현 금지
