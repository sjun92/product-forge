# Bug Investigator

버그의 원인을 찾고 최소 수정 계획을 세운다. 승인 전에 코드를 바꾸지 않는다.

---

## 호출 즉시 시작

스킬이 호출되면 **스킬 소개 없이 바로** 아래를 수행한다.

### Ruflo MCP 가용성 확인

`.mcp.json`의 `claude-flow` 서버 설정과 세션 내 MCP 도구 활성 여부를 확인한다.

- **활성 상태**: `claude_flow_spawn_agent` 등 ruflo 도구로 하위 에이전트를 위임한다.
- **비활성 상태**: "Ruflo MCP가 비활성 상태입니다. Claude가 직접 조사를 수행합니다."라고 한 줄 고지 후 진행한다. Ruflo를 사용했다고 말하지 않는다.

### 항목 파악 및 시작

1. 현재 대화에서 아래 6개 항목 중 이미 언급된 것을 파악한다.
2. 파악된 항목은 **추천값으로 제시**하며 맞는지 확인한다.
3. 파악되지 않은 항목은 **기대 동작 → 실제 동작 순서**로 하나씩 질문한다.

예시 — 사용자가 "새로고침하면 로그인이 풀려"라고만 한 경우:

> 기대 동작은 **새로고침해도 로그인 상태가 유지되는 것**이고,
> 실제 동작은 **새로고침 시 로그인 화면으로 이동**하는 것으로 잡을게요. 맞나요?
> 재현 순서는 어떻게 되나요? 로그인 → 특정 페이지 이동 → 새로고침 순서인가요?

항목이 전혀 없는 경우: "원래 어떻게 동작해야 하나요?"로 시작한다.

---

## 1단계: 항목 채우기

아래 6개 항목을 순서대로 채운다.  
**항목당 하나씩** 질문한다. 이미 말한 내용은 다시 묻지 않는다.  
현재 대화나 코드베이스에서 추론할 수 있으면 **추천값을 먼저 제시**하고 맞는지 확인한다.

### 항목 1: 기대 동작
> "원래 어떻게 동작해야 하나요?"

**추천 방법**: 사용자가 이미 설명한 경우 그 내용을 한 줄로 요약해 제시한다.  
예) "새로고침해도 로그인 상태가 유지돼야 한다 — 이렇게 잡을까요?"

### 항목 2: 실제 동작
> "지금 실제로 어떻게 되나요?"

**추천 방법**: 이미 언급된 증상을 구체화해 제시한다.  
예) "특정 페이지에서 새로고침하면 로그인 화면으로 이동 — 맞나요?"

### 항목 3: 재현 순서
> "문제가 생기는 단계를 순서대로 알려주세요."

**추천 방법**: 기대/실제 동작에서 흐름을 추론해 제시한다.  
예) "로그인 → /search 이동 → 새로고침 — 이 순서인가요?"  
재현이 불규칙하면 "가끔 발생"이라고 써도 된다고 안내한다.

### 항목 4: 실행 환경
> "어떤 환경인가요? OS, 브라우저, 개발/배포 중 어디서요?"

**추천 방법**: 이전 대화에서 언급된 환경을 제시한다.  
예) "Windows + Chrome, localhost 개발 서버 — 맞나요?"

### 항목 5: 오류 메시지
> "콘솔이나 로그에 오류 메시지가 있나요? 민감정보는 제외하고 붙여주세요."

없으면 "오류 없음"으로 넘어간다고 안내한다.

### 항목 6: 최근 변경
> "최근에 관련 코드를 바꾼 게 있나요?"

**추천 방법**: 현재 Git 변경분이 파악된 경우 언급한다.  
예) "최근 auth/router.py가 변경됐습니다. 관련이 있을 수 있어요 — 알고 계셨나요?"  
없으면 생략 가능하다고 안내한다.

## 2단계: 완성된 내용 확인

6개 항목이 채워지면 아래 형식으로 한 번 보여준다.

```
기대 동작: {기대 동작}
실제 동작: {실제 동작}
재현 순서: {재현 순서}
실행 환경: {실행 환경}
오류 메시지: {오류 메시지}
최근 변경: {최근 변경}
```

> "이대로 조사를 시작할까요?"

## 3단계: 조사 실행

확인이 되면 아래를 수행한다.

```
Ruflo 멀티 에이전트 방식으로 아래 버그를 조사해줘.
기대 동작: {기대 동작}
실제 동작: {실제 동작}
재현 순서: {재현 순서}
실행 환경: {실행 환경}
오류 메시지: {오류 메시지}
최근 변경: {최근 변경}
분석 담당은 재현 조건과 원인 후보를,
테스트 담당은 원인을 구분할 수 있는 검증 방법을 찾아줘.
추측을 사실처럼 말하지 말고 근거와 함께 정리해줘.
수정 전에는 원인, 최소 수정 계획, 영향받는 파일을 보여주고 멈춰줘.
내가 승인하면 수정하고, 가능하면 수정 전 실패·수정 후 통과하는
회귀 테스트로 확인해줘.
재현하지 못했다면 그 사실과 추가로 필요한 정보를 알려줘.
```

---

## 제약

- 조사 단계에서는 소스·설정 파일 수정 금지
- 비밀값·개인정보 원문 출력 금지
- 추정은 `[추정]`, 확인된 사실은 `[사실]`로 구분
- 파일 경로와 근거를 함께 제시
- 승인 전 수정 금지
- 재현 실패 시 "수정 완료" 대신 "추가 정보 필요" 상태로 종료
