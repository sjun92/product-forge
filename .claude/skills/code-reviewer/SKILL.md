# Code Reviewer

파일을 바꾸지 않고 코드를 정적으로 검토한다. 명령 실행이 필요하면 먼저 묻는다.

---

## 호출 즉시 시작

스킬이 호출되면 **스킬 소개 없이 바로** 아래를 수행한다.

### Ruflo MCP 가용성 확인

`.mcp.json`의 `claude-flow` 서버 설정과 세션 내 MCP 도구 활성 여부를 확인한다.

- **활성 상태**: `claude_flow_spawn_agent` 등 ruflo 도구로 하위 에이전트를 위임한다.
- **비활성 상태**: "Ruflo MCP가 비활성 상태입니다. Claude가 직접 리뷰를 수행합니다."라고 한 줄 고지 후 진행한다. Ruflo를 사용했다고 말하지 않는다.

### 항목 파악 및 시작

1. 현재 대화에서 검토 범위와 관점이 이미 언급됐는지 파악한다.
2. 파악된 항목은 **추천값으로 제시**하며 맞는지 확인한다.
3. 파악되지 않은 항목은 **검토 범위부터** 질문한다.

예시 — 사용자가 "auth 폴더 리뷰해줘"라고만 한 경우:

> 검토 범위는 **auth/ 폴더 전체**(router.py, jwt_utils.py, dependencies.py)로 잡을게요. 맞나요?
> 관점은 구조·오류·테스트·보안 4개를 기본으로 볼게요. 제외하거나 집중할 것이 있나요?
> (아까 분석에서 `secure` 쿠키 플래그 누락이 나왔는데, 보안 관점을 우선할까요?)

항목이 전혀 없는 경우: "어느 파일이나 폴더를 봐드릴까요?"로 시작한다.

---

## 1단계: 항목 채우기

아래 2개 항목을 순서대로 채운다.  
**항목당 하나씩** 질문한다. 이미 말한 내용은 다시 묻지 않는다.  
현재 대화나 코드베이스에서 추론할 수 있으면 **추천값을 먼저 제시**하고 맞는지 확인한다.

### 항목 1: 검토 범위
> "어느 부분을 봐드릴까요?"

**추천 방법**: 최근 대화에서 언급된 파일·폴더·변경분을 제시한다.

| 상황 | 추천 예시 |
|------|-----------|
| 방금 특정 파일 얘기를 한 경우 | "auth/router.py와 auth/dependencies.py로 할까요?" |
| Git 변경분이 있는 경우 | "현재 Git 변경분(staged+unstaged)으로 할까요?" |
| 보안 얘기가 나온 경우 | "auth/ 폴더 전체로 할까요?" |
| 아무 맥락이 없는 경우 | "폴더명, 파일명, 또는 'Git 변경분'으로 알려주세요." |

### 항목 2: 관점
> "특별히 집중해야 할 관점이 있나요?"

**추천 방법**: 기본 4개를 제안하고 제외할 것이 있는지 묻는다.

기본 관점:
- 구조와 유지보수성
- 오류 가능성과 경계 조건
- 테스트 누락
- 인증·권한·민감정보 처리

> "이 4개로 볼까요? 제외하거나 추가할 관점이 있나요?"

**추천 방법**: 검토 범위에서 이미 파악된 위험 항목이 있으면 언급한다.  
예) "아까 분석에서 `secure` 쿠키 플래그 누락이 나왔는데, 보안 관점에 집중할까요?"

---

## 2단계: 완성된 내용 확인

2개 항목이 채워지면 아래 형식으로 한 번 보여준다.

```
검토 범위: {검토 범위}
관점:
- {관점1}
- {관점2}
- ...
```

> "이대로 리뷰를 시작할까요?"

---

## 3단계: 리뷰 실행

확인이 되면 아래를 수행한다.

```
Ruflo 멀티 에이전트 방식으로 코드 리뷰만 해줘.
검토 범위: {검토 범위}
관점:
{관점 목록}
소스·설정 파일을 수정하거나 의존성을 설치하지 마.
이번에는 정적 검토만 하고 명령 실행이 필요하면 먼저 알려줘.
비밀값이나 개인정보 원문을 답변에 포함하지 마.
발견 사항을 심각한 순서대로 정리하고, 각 항목에
파일 경로와 위치, 발생 조건, 영향, 근거, 해결 방향을 적어줘.
취향 수준의 제안과 실제 오류 가능성을 구분해줘.
문제를 찾지 못했다면 검토 범위와 남은 한계를 설명해줘.
```

---

## 제약

- 소스·설정 파일 수정 금지
- 의존성 설치 금지
- 비밀값·개인정보 원문 출력 금지
- 추정은 `[추정]`, 확인된 사실은 `[사실]`로 구분
- 파일 경로와 근거를 함께 제시
- 명령 실행 전 사용자에게 먼저 알림
